The daemon updates live. The kernel reports each change, so nothing is rescanned.

Follows every disk change

One fanotify mark covers a whole filesystem, Btrfs subvolumes included.

  • created/srv/backups/db-2026-11-24.zst2 s
  • renamed~/photos → ~/archive/photos9 s
  • removed/tmp/build-7f2c14 s
  • created~/src/api/target/release/api31 s
  • removed~/.cache/pip/http48 s
  • renamed/srv/media/inbox → /srv/media/20261 m

Rescans only changed folders

Daily scans skip folders whose timestamps match the index; a full check runs weekly.

Moves renamed folders in one step

On Linux 5.17 and later a rename updates one row, however large the folder.

# fanotify FAN_RENAME
old  /srv/media/inbox        id 48211
new  /srv/media/2026         id 48211

UPDATE nodes SET parent = 3907, name = '2026'
  WHERE id = 48211;      -- 1 row, 31,402 entries moved

Restarts the daemon when it stalls

A watchdog logs the stuck step and exits after 15 minutes, so systemd resumes the scan.

$ journalctl -u disko
fanotify covers 6 device IDs on 3 filesystems
resuming interrupted scan: 5,290 directories pending
deep scan checked 12,318,655 entries in 3,029s
watching  0 metadata errors, 0 watch errors

Install Disko in 3 steps

Linux with systemd, Rust 1.88 or later and SQLite. The build script installs what is missing on Arch, Debian, Fedora, openSUSE and Alpine.

1

Clone the repository

Everything lives in one repository.

$ git clone \
    https://github.com/olibuijr/disko.git
$ cd disko
2

Build and install the service

Runs the tests, installs the binary and starts the daemon.

$ ./build.sh --test --install
Dashboard password: printed once
Disko is running on port 7331
3

Open the dashboard

Or ask the index from a shell.

# http://localhost:7331
$ disko largest --kind dirs
$ disko --json du /srv

Questions about Disko

Does Disko read file contents?

No. It records names, sizes, owners and timestamps, never file contents, and does not follow symlinks.

How much memory does the daemon use?

About 90 MB resident while watching an index of 12 million entries, with a 64 MiB SQLite cache.

Which Linux systems does it support?

Linux. Filesystem-wide watching needs fanotify; older kernels and other setups fall back to inotify.

Can I put Disko on the internet?

Keep it on a trusted network or behind an HTTPS proxy or SSH tunnel. Passwords are stored as Argon2id hashes.

$ disko --json info ~/src/api
{
  "path": "/home/dev/src/api",
  "kind": "dir",
  "allocated": 16012595200,
  "files": 48211,
  "entries": 51906,
  "modified": "2026-11-24T16:02:11Z",
  "uid": 1000
}

Every command prints JSON with --json, and disko sql runs read-only queries for scripts and agents.
